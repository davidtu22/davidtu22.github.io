Projects

I use AI heavily to build these, and this isn't the site where I'd pretend otherwise. But there's a real difference between procedural generation — rules producing structured variety, which is what actually makes something like Infinite Craft or a roguelike work — and generative AI, a model producing content wholesale. I care which one I'm reaching for, and why. I want to understand the code underneath what I ship, and there are things — the writing and art direction that make Disco Elysium what it is, for one — I don't think generative AI should touch. I care about a tool's effect as much as its affect: what it produces, and what it does to the person using it.

Fig. 2 — Want to build

A word-forge roguelite

Infinite Craft's combination mechanic is procedural generation doing something that looks a lot like generative AI's job, through much simpler rules — which is exactly why it's interesting to me. I want to build a roguelite around it: instead of racing strangers to a shared target word, you're combining elements under pressure to forge the one word that beats the boss in front of you.

Speedrunners already treat Infinite Craft like a competitive sport. I want to make that explicit.

Infinite Craft Lite — case study

A static Infinite Craft clone, and what “procedural” stops meaning once an LLM is doing it

A first, smaller step toward the roguelite above: I built a working Infinite Craft clone, then got more interested in the architecture underneath it than the game itself. Neal Agarwal's real version doesn't hard-code any combinations — every new pairing anyone tries gets sent live to an LLM (Llama 2, via Together.ai), and the result is cached forever after. That's the actual distinction from the entry above, made concrete: my clone's combine logic is procedural generation in the classic sense — a fixed rule table, zero marginal cost, the same result every time. Infinite Craft's is generative AI doing that same job at runtime, for as long as the game exists.

I wrote up the economics of that difference as a case study — AI Dungeon's 2021 model swap (and the quality drop players immediately noticed) is the cautionary tale for what “runs on an LLM, forever” actually commits you to. I also built and tested a small proof-of-concept backend (Claude Haiku 4.5) that generates genuinely novel combinations, but deliberately never deployed it for open play — the deployed demo below stays fully static on purpose.

A longer piece on this is coming to Writing.

Fig. 3 — Want to build

A thought cabinet for every RPG

Disco Elysium's skills aren't stat sticks — each one has a voice, a personality, an argument with you. I want to build toward something like it: a system where what you wear doesn't just add or subtract points, but combines with your build to produce new archetypes, the way the Thought Cabinet turns ideas into permanent traits.

Longer term, I want to port that depth to games like Baldur's Gate 3, where the full subclass catalogue only really exists behind third-party mods. Which means the actual prerequisite is learning how modding and engine-level systems work — not just designing the spreadsheet.

Fig. 4 — First reps

Unity recreations of Flappy Bird & the Chrome Dinosaur game

Baseline reps, not the destination — built in C# and Visual Studio: 2D physics, collision, object spawning/destruction, scoring, UI, sound, and animation, all from scratch.

Used Time.deltaTime for hardware-independent movement and iterated on collider dimensions and object lifecycle to tune gameplay consistency, perceived fairness, and performance.
